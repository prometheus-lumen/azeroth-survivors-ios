# 网页游戏 iOS 客户端交付检查

适用于本地 HTTP 资源服务加 WKWebView 的客户端。后续游戏在复用代码前逐项检查，按游戏实际功能增减；编译通过不能替代真机验证。

## 包与安装

- 检查 ZIP、主程序权限、arm64 真机平台、Bundle ID、版本、设备族、最低系统、图标资产目录和所需资源。
- 未签名包与已签名包明确区分。需要排查签名时读取用户实际保留的签名产物，不能用原始未签名文件代替，也不能因结果已删除而推断用户没签过。
- 没有系统安装确认框时，先区分签名工具的 OTA 入口与系统包校验；同一个已签名包可用配对 Mac 直接安装，保存系统返回结果。
- 静态检查中的可疑差异只是线索。PokéIsaac 的实测记录中，签名和描述文件的 App ID 与 CFBundleIdentifier 后缀不同，但目标 iPad 仍接受了该签名包；不能把这个差异单独宣布为安装失败根因。
- 不为排查而先卸载带数据的 App。更新保留包标识和数据；新包成功验证后才替换桌面文件。

## 启动与本地服务

- 仅绑定回环地址。NWListener 的端口只设置一次；同时在 requiredLocalEndpoint 和 on 参数中设置会被 Network.framework 拒绝。
- 本地服务启动异步完成，失败和超时可见，避免主线程同步等待触发启动 watchdog。
- 端口及 WebView origin 保持稳定，避免无故丢失登录态或本地存储。
- 实测根页面、JS、字体、素材、HEAD、有效和无效 Range、路径边界；WASM 需要正确 MIME 和足够的文件大小限制。
- 保持原应用生命周期；旧式 UIWindow 入口不要误加 SceneManifest。

## 真机网络与游戏行为

- 分开检查本地资源、官网、账号 API、素材 CDN 和实时连接。素材曾成功下载不能证明账号连接正常，某个 API 失败也不能称为整机断网。
- 在真机 WebKit 验证，而非只在桌面 Chrome 验证。记录 secure context、系统路径、HTTP 状态或具体传输错误。
- 诊断不记录请求正文、密码、令牌、Cookie 或 URL 查询参数；日志、签名包和证书不进入公开仓库。
- 需要登录时验证实际邮箱登录流程；OAuth、邮件验证、密码重置回跳与 WebSocket 分别检查，不能由 CORS 预检成功推定全部正常。
- 不对写入请求做无条件网络重试，避免重复提交对局或奖励。
- 检查触控、横屏、音频、前后台恢复、存档和更新。没有真实验证的项目明确标记待验证。
- 游戏若需要 WebGPU，核对最低系统与真机 GPU 能力；不能只把最低系统版本沿用上一款。

## 更新与开源

- 核心文件整组下载完成后再切换；不能在游戏过程中自动重载。
- 本地生成的字体文件不应当作官网原始路径重新下载。
- 开源客户端代码、原创图标和构建脚本，排除游戏官网资源、用户数据、证书和私有安装链接。
- 公开发布前确认本地验证结果与仓库源码对应；安装、启动、联网、游玩分别报告，不相互替代。
